# Autonomous Career Advisor

A multi-agent LLM system for **skill gap analysis and learning path generation**.
Final year project — Education + Career Planning domain.

Base paper: *EduPlanner: LLM-Based Multiagent Systems for Customized and Intelligent
Instructional Design* (IEEE Transactions on Learning Technologies, 2025). See
`Career_Advisor_Project_Analysis.docx` for the full gap analysis and novelty argument.

## Architecture

```
             ┌─────────────────┐      ┌──────────────────┐
 resume ───► │ Profile Agent   │      │ Market Demand    │ ◄─── job postings
             │ (LLM extract +  │      │ Agent (RAG over  │      (sample / Adzuna)
             │  taxonomy map)  │      │  postings, with  │
             └────────┬────────┘      │  evidence trail) │
                      │               └────────┬─────────┘
                      ▼                        ▼
             ┌────────────────────────────────────┐
             │ Skill-Gap Engine (deterministic:   │
             │ taxonomy set-difference, priority  │
             │ = demand share × mastery gap)      │
             └────────────────┬───────────────────┘
                              ▼
             ┌─────────────────────────┐   revise    ┌──────────────────────┐
             │ Curriculum Planner      │ ◄────────── │ Verifier/Critic      │
             │ (LLM objectives over    │ ──────────► │ (FGCR rubric: Feasi- │
             │  retrieved courses +    │   verify    │ bility, Groundedness,│
             │  prerequisite topology) │             │ Coverage, Realism)   │
             └─────────────────────────┘             └──────────┬───────────┘
                                                          pass  ▼
                                                        learning path
```

Orchestrated with **LangGraph** (plan → verify → revise loop, max 2 revisions).
LLM: **Groq** (Llama 3.3 70B for planning/critique, Llama 3.1 8B for extraction).
Embeddings/RAG: **ChromaDB** with built-in ONNX MiniLM (no GPU, no key needed).

### Research contributions (vs. base paper & related work)

| Contribution | Gap it addresses |
|---|---|
| Live-capable Market Demand Agent with per-skill evidence (posting IDs) | EduPlanner has no market dimension; GenMentor uses a static LinkedIn snapshot |
| Deterministic taxonomy-anchored gap engine (auditable, not prompt-guessed) | GenMentor's LLM-judged gaps; EduPlanner's subject-locked Skill-Tree |
| Verifier agent with FGCR rubric + hard rule checks that cap LLM scores | No output verification in any cited system |
| Resources retrieved from a catalog — the LLM can never invent a course | Hallucinated-resource failure mode |
| Graceful no-LLM degradation (keyword extraction, rule-only verification) | Cost/robustness concerns raised in EduPlanner |

## Setup

### Backend (Python 3.11+)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
copy .env.example .env          # then add your free GROQ_API_KEY (console.groq.com)
uvicorn app.main:app --reload --port 8010
```

Works without a key too — agents fall back to deterministic mode (keyword skill
extraction, rule-only verification), useful for testing the pipeline.

### Frontend (Node 18+)

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 (expects backend on :8010)
```

### Tests (offline, no API key needed)

```bash
cd backend && .venv\Scripts\python -m pytest tests/ -v
```

## Data

- `backend/app/data/jobs_sample.json` — **synthetic** postings (generated by
  `backend/scripts/generate_data.py`, seeded) so everything runs offline.
  Switch to real data with `JOB_PROVIDER=adzuna` + API keys in `.env`.
- `backend/app/data/skills_taxonomy.json` — curated ESCO-style taxonomy
  (77 tech skills with aliases + prerequisite DAG). Extend with the full
  ESCO download for the final evaluation.
- `backend/app/data/courses_sample.json` — real, well-known free courses
  (Coursera, freeCodeCamp, official docs, Kaggle Learn, …).

## API

- `GET /api/health` — status, LLM availability, collection counts
- `GET /api/roles` — roles the current job provider can serve
- `POST /api/advise` — `{resume_text, target_role, hours_per_week, education}`
  → full `AdvisorResult` (profile, demand with evidence, gap report, verified path, FGCR critique)
